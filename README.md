# 电源柜调试记录

面向电力现场（馈电柜 / 直流屏等柜子调试）的调试日志安卓应用。数据存储于手机本地 SQLite；**仅在用户主动配置并使用 WebDAV 同步时才访问自己指定的服务器**，不集成任何第三方 SDK。

## 功能总览

- **项目制管理**：以工程项目为根，一个项目包含一台或多台柜子
- **柜子类型（模板）**：如“直流馈线柜”，每个类型维护一份**预选测试项候选池**；保存日志时测试内容自动沉淀进候选池（自动去重），支持单条删除、批量粘贴导入
- **预选待测（v2.4 三态）**：建柜子自动生成该柜的测试清单；长按柜子「开始测试」逐项 ✓通过 / ✗未通过（强制填故障现象，自动生成故障记录）；未通过项下次继续出现在清单里供复测，复测✓才转绿；手动写日志保存时自动把内容命中的项标"通过"（忽略行尾标点的宽容匹配）。项目卡/柜子行实时显示 待测·未通过·待处理故障 三个数字
- **调试员名单（v2.5）**：与登录账号无关的现场调试人员名册，由**超级口令**统一维护（添加/改名/删除均需验证）；写日志和开始测试时「测试人员」自动使用本机绑定的**当前调试员**（v2.6 起不再每次填写、绝不回落到登录账号），点击可切换；改名/删除不影响历史日志；名单随备份与 WebDAV 同步互通到全队
- **定向导出（v2.6）**：项目卡长按「导出本项目日志」、柜子长按「导出本柜日志」，Excel 双表格式与全量导出一致
- **开始测试页（v2.6）**：待办项下方只读展示已通过项（绿色✓+完成时间）；复测点通过时，该项此前登记的未解决故障**自动转为已解决**
- **操作习惯（v2.6）**：单击柜子直接进入开始调试（未建清单则先跳预选待测）；长按菜单改为 编辑柜子/预选待测/新建日志/导出本柜/删除
- **常用模板与候选手选（v2.9）**：项目卡长按「加入常用模板」把项目各柜启用的待测项沉淀为类型候选池条目；「从候选池补充」改为弹出手选器——候选项按**使用频次降序**（该类型所有柜子清单中出现次数），支持长按拖动连续多选、「常用选取」（使用≥2次一键勾选）、全选、清空
- **跨柜拉取（v2.9）**：柜子长按「从别的柜子拉取预选待测」，弹出全库柜子列表可按**项目名/柜子名/设备编号搜索**，选中后用来源柜启用清单整体覆盖本柜清单（旧项删除并同步全队）
- **删除同步（v2.9 墓碑机制）**：所有删除入口写入删除墓碑并随快照上传，其他手机合并时自动删掉对应记录——删除不再"这边删了那边长回来"
- **诊断日志（v2.10）**：数据工具页新增「查看同步日志」——同步全过程（目录/文件清单/每份快照的合并统计或失败原因）与**全局崩溃记录（黑匣子）**都落在应用内，可一键复制发回排查"两台手机看不到彼此数据""闪退白屏"类问题
- **快照压缩（v2.10）**：WebDAV 快照改为 gzip 压缩上传（中文 JSON 通常压到原来的 1/8~1/15），读取按魔数自动识别新旧格式，旧版明文快照照常合并
- **下载修复（v2.11，关键）**：修复 GET 请求误带空请求体被坚果云拒绝（`method GET must not have a request body`）导致**合并他人快照自团队互通功能上线以来从未成功**的问题——该错误此前被静默吞掉，表现为"两台手机互相看不到数据"；v2.10 的诊断日志使其现形
- **手选器涂选重做（v2.12）**：修复长按拖选把列表冻死（旧版 suppressLayout 方案）的问题——现在长按进入涂选态后列表照常滚动，手指划过/滚动经过的行连续勾选；跨柜拉取异常改为完整堆栈落盘诊断日志，便于远程定位
- **添加联想（v2.13）**：预选待测页手动添加自定义项时，输入框下方实时列出候选池中**包含输入文字**的相似项（标注使用次数/"已在本柜"），点选回填标准描述再添加——避免描述有几个字差异造成重复测试项；修复跨柜拉取确认框因 getString 参数与占位符错位导致的崩溃（`IllegalFormatConversionException`）
- **解决方法全链路（v2.19）**：故障列表点「通过」弹窗填写**解决方法**（可留空，同时保存在故障记录上）；消除流水条目直接显示「方法：xxx」，点击可随时编辑/补充并同步到日志页同时间线；故障列表最后一个故障确认消除后**自动将该测试项标记通过并生成通过日志**，测试列表只有一个未解决故障时点通过会同时生成消除+通过两条日志
- **幽灵状态自愈（v2.20）**：凡测试项标记「未通过」但关联故障记录已全部不存在（界面会显示"原因见日志"、故障列表却为空——来源于删除日志、旧快照合并或历史版本残留），一律自动纠正为「测试通过」。应用启动、删除日志后、进入测试清单/预选待测页时均会执行；故障记录仍存在的项（含已解决待复测）不受影响，遵守「故障已解决必须人工复测」规则
- **删除"新者胜"（v2.21，关键）**：修复"旧机删除清掉他机较新数据"根因——墓碑此前无条件永不失效。现在合并时任何一行（本机存活或快照携带）的 `updatedAt` 晚于其墓碑 `deletedAt`，则判定墓碑被击败并自动清理，该行保留/插入、全端收敛回存活；只有删除确实晚于该行已知全部更新时才生效（级联）。三机互相同步后"故障/消除/通过记录全没了"的问题从此免疫
- **从备份找回被删记录（v2.22）**：数据工具页新增「找回」工具——扫描所选备份（明文 JSON 或 WebDAV gzip 快照均可，按魔数自动识别）中本机已缺失的记录并**权威插回**：找回行全部刷新 `updatedAt`=当前时刻并清除陈旧删除墓碑，下次同步即以"新者胜"传播回全队（其余手机无需手动操作）。一旦同步过的手机全丢了历史数据，用旧备份即可把故障/消除日志整体捞回；仅需一台手机执行
- **找回预览·日志构成（v2.23）**：找回扫描后若"备份中无本机缺失记录"，不再只弹一句"无需找回"，而是展示**备份 vs 本机**的日志构成对比（总日志 / 通过 / 故障 / 消除 / 故障记录条数）——用户据此判断所选备份是否为丢失之前的产物（备份中故障/消除日志为 0 = 该备份生成于丢失之后，应改选更早备份如坚果云文件历史重试）；有可找回内容时预览计数与真实执行取自同一扫描逻辑，口径一致
- **日志类型修复（v2.25，关键）**：数据工具页「修复日志类型」把**被故障记录指向、却显示为「通过」**的日志重分类为「故障」，并把**备注=已解决故障现象、同柜同测试内容**的日志重分类为「消除」（消除+解决方法重新显示）。成因：v2.18 之前产生的数据（及后来被旧格式快照/旧备份合并进来的行）没有 `logType` 字段，系统迁移默认值=0，于是"故障/消除"看着像消失了，其实日志行与故障记录（现象/解决/已解决状态）一直都在，只是归类标注被冲成「通过」。修复只改类型标注、不增删数据，刷新时间戳后下次同步以"新者胜"传播回全队；修复记录存本机，配「撤销类型修复」一键还原（仅对 v2.25 之后执行的修复生效）
- **按项目增量同步（v2.26，★架构升级）**：云端改为「**全局区 + 每项目一个文件夹**」新结构，同步只搬运有改动的数据（规格第 7 章）：
  - 云端布局：`global/backup_<账号>_<本机标识>.json`（柜子类型、候选池、调试员名单、**全部删除墓碑含项目级**）与 `projects/project_<项目UUID>/backup_<账号>_<本机标识>.json`（该项目全部柜子/日志/故障/预选项 + 项目行）
  - **本地修改检测用「项目版本时钟」**（=该项目所有行最大 `updatedAt`），不信任安卓文件 mtime；本机任一项目下增删改会推高该项目时钟，时钟晚于上次同步时刻才重新上传——按项目只同步对应数据，全量→增量大幅省流量、冲突半径缩到单项目
  - 墓碑统一走**全局区**传播（删除墓碑不涉及具体项目归属，避免为追溯所属而扩充 `deleted_items` 结构），项目级删除走独立 `deleted_projects` 表、同样"新者胜"
  - **时区/时钟偏差兜底（v2.26）**：快照头部写 `deviceTimeZoneOffset`（毫秒）；合并前检测"同一条目本机与云端在同一分钟窗口内各有更新"的歧义，手动同步时弹窗让用户选「保留本地 / 覆盖云端」，自动同步默认墙钟新者胜不弹窗
  - **旧版数据迁移（v2.26）**：登录弹窗新增「旧版数据目录（迁移用）」——填旧版 v2.x 的 WebDAV 目录，首次同步自动把旧全量快照按项目拆解分发进新结构（已迁移文件名记本机，不删不改旧文件，旧版设备照常工作）；不填则仅用新结构
  - 达到规格第 7.0 三条硬需求：全局数据不丢、按项目增量、独立文件夹并可读旧数据
  - 数据工具页「立即同步」遇时钟歧义弹窗裁决；同步日志照常记录阶段清单与每次合并统计
- **日志类型随快照同步（v2.27，关键）**：修复新版快照序列化漏写 `logType` 的先天缺陷——v2.26 生成的 global/项目快照都不含该键，多端同步合并后故障/消除日志会被当成「通过」显示（行数据没丢，同 v2.25 描述）。v2.27 起 `logJson` 补写 `logType`、三处读取（全量/合并/恢复）识别该键，**新同步不再重演分类回退**；备份 schemaVersion 10→11，旧快照缺键按 0 兼容解析
- **自定义行分配高效选柜（v2.28）**：排列方式的选柜弹窗升级——顶部搜索框按柜名/精简名即时过滤；**已在其他排的柜子置灰标「已在第N排」、不可重复选择**（不再出现在可选列表里）；未分配柜子置顶、连续点选加入本排（不关弹窗），一排加多个柜子不再反复开关弹窗
- **柜子实例**：现场实际设备（如“1号直流馈线屏”），隶属某项目、绑定某类型；同型号柜子共用同一套候选池。字段：名称必填，设备编号 / 安装位置 / **安装人员** 选填
- **调试日志**：
  - 项目→实例 两级定位后，自动加载该类型候选池，勾选后一键填充测试内容（可手改）
  - 回路号自由输入 + 历史回路联想下拉，留空即整柜测试
  - 每条日志可挂多条故障：故障回路 / 问题现象 / 解决方法 / 发生时间（默认当前可改）/ 解决完成时间 / 状态（待处理↔已解决）
  - 日志编辑、删除（级联删故障）
- **查询筛选**：项目 / 类型 / 实例 三级联动 + 故障状态（含待处理 / 已全解决）+ 回路号筛选 + 全文搜索（测试内容、备注、测试人、故障现象、解决方法）
- **数据工具**：
  - 导出全部日志为标准 **.xlsx**（两个工作表：调试日志、故障记录；A4 打印适配——一页宽缩放、每页重复表头、冻结首行、列宽自适应；故障表横向打印；日志表含创建/修改账号列）
  - JSON 备份 / 恢复（恢复前强提示覆盖；兼容 v1 旧备份自动迁移）
  - **从备份找回被删记录**（v2.22）：扫描备份中本机缺失的记录权威插回并刷新时间戳、清除陈旧删除标记；明文/gzip 均支持，找回结果靠同步传播回全队。v2.23 起"无缺失记录"时展示备份 vs 本机日志构成对比，帮用户判断所选备份是否为丢失前的产物（避免找了无果却不知为何）
  - **修复日志类型**（v2.24）：把被故障记录指向却显示为「通过」的日志重分类为「故障」；v2.25 扩展为同时把备注=已解决故障现象的日志重分类为「消除」并支持「撤销类型修复」
- **测试账号与 WebDAV 同步**：
  - 登录验证即 WebDAV 连通性（PROPFIND + Basic 认证），无独立账号体系；登录弹窗内置**「测试连接」**按钮，失败时显示完整诊断报告（HTTP状态码/响应头/排查提示），可复制发回定位
  - 登录后：新建日志自动绑定"测试人员"，每条日志记录**创建账号/修改账号**并在列表、编辑页、导出 Excel 中展示
  - **超级口令** `mz9890517`：在登录框密码栏输入即可离线直接注册本地测试员（免服务器）
  - **团队互通零操作（v2.26 增量同步）**：所有手机配置**新版 WebDAV 目录**（新文件夹，不复用旧版 `backup_*.json` 所在目录），每台手机上传自己的全局快照与各项目快照（文件名均带设备唯一标识：同一账号多台手机不互覆），同时把云端所有全局/项目快照拉取合并进本机——记录自动汇到每台手机上；目录结构直观、只同步有改动的项目
  - 自动时机：打开应用时增量同步（60秒节流）；另有手动「立即同步」按钮（遇时钟歧义弹窗选「保留本地/覆盖云端」）
  - 合并规则：按 UUID 主键去重、同 ID 冲突保留 `updatedAt` 较新者；**删除通过墓碑传播且同样"新者胜"**：合并端先落库远端墓碑，再把每行墓碑的 `deletedAt` 与本机存活行 ∪ 快照携带行的最新 `updatedAt` 比对——删除早于该行更新 → 墓碑"被击败"、自清理并保留/插入该行；删除晚于该行已知全部更新 → 才应用删除（含级联）。既防止被删数据借旧快照复活，也防止旧机/旧快照里的旧删除清掉其他手机上较新的故障/消除/通过数据（v2.21）
  - **旧版兼容**：登录弹窗填「旧版数据目录」后，首次同步自动读取 v2.x 的 gzip 全量快照（schemaVersion=9，魔数识别）并入本机库，再按项目时钟分发进新结构；旧文件不改不删，旧版设备继续读写旧目录直到全队升级完毕
  - 支持 http 明文（内网 NAS 场景）与中文路径

## 签名说明

**v2.26 起是新软件/新签名**：包名 `com.powerdebug.record`，与老项目（≤v2.25、`com.fieldlog.powerdebug`）正式分家，老版本用户需卸载后安装新包。本线所有版本（debug/release）统一使用固定密钥（alias: powerdebug），保证本线任意版本可直接覆盖安装。

**密钥保管方式**：仓库内只有加密压缩包 `app/signing/powerdebug.keystore.zip`，解压密码不在仓库中（由项目所有者掌握）。构建时由 GitHub Actions Secrets 自动完成：`SIGNING_ZIP_PASSWORD` 解压密钥、`SIGNING_STORE_PASSWORD`/`SIGNING_KEY_PASSWORD` 注入签名。原始 .keystore 文件不入库。

新会话/新维护者需要本地解包签名时，请向项目所有者索取压缩包密码；CI 构建无需人工介入。

```
                        └─1─N DebugLog 1─N FaultRecord
```

- 删除均为级联删除且删除前有数量警告弹窗；显式删除入口同时写入 `deleted_items` 墓碑（DB v6）；**项目级删除另写独立 `deleted_projects` 墓碑表（DB v11）**，随全局区同步传播到全队
- 候选池 `(typeId, content)` 唯一索引兜底去重
- 同步文件分两种（DB v11 / 备份 schemaVersion=11）：`readyKind="global"` 全局区（类型/候选池/调试员/墓碑）与 `readyKind="project"` 单项目（项目+柜子/日志/故障/预选项），字段名=列名，PC/网页端可各自独立解析

## 后期电脑端 / 网页端接入指南（预留设计）

1. **JSON 即交换格式**：备份文件字段名 = 数据库列名（见下），任何平台解析该 JSON 即可获得全部业务数据。
   ```json
   {
     "app": "power-debug-log",
     "schemaVersion": 11,
     "projects":      [{ "id","name","code","remark","createdAt","updatedAt" }],
     "cabinetTypes":  [{ "id","name","remark","createdAt","updatedAt" }],
     "candidateItems":[{ "id","typeId","content","createdAt","updatedAt" }],
     "instances":     [{ "id","projectId","typeId","name","deviceCode","location","installer","createdAt","updatedAt" }],
     "logs":          [{ "id","instanceId","circuit","testContent","logType","tester","remark","createdBy","updatedBy","createdAt","updatedAt" }],
     "faults":        [{ "id","logId","circuit","symptom","solution","occurredAt","resolvedAt","status","updatedAt" }],
     "plannedItems":  [{ "id","instanceId","content","enabled","doneAt","logId","result","faultId","createdAt","updatedAt" }],
     "debuggers":     [{ "id","name","createdAt","updatedAt" }],
     "deletedItems":  [{ "id","tbl","itemId","deletedAt" }],
     "deletedProjects":[{ "id","projectId","deletedAt" }]   // v11：项目级删除墓碑
    }
    ```
    - `schemaVersion=11`；新结构文件带 `readyKind`（full/global/project）与 `deviceTimeZoneOffset`（时区偏移毫秒，同步冲突裁决用）
    - v2 起所有 `id` 为客户端生成的 UUID 字符串（多设备离线新增不撞主键）；`updatedAt` 为合并时钟。
    - 应用仍可导入 `schemaVersion: 1` 的旧备份（自动生成 UUID 并重映射引用）。
2. **复用路径 A（Kotlin 多端）**：`data/db/Entities.kt` 与 `Repository.kt` 无 Android UI 依赖（仅依赖 Room 与 kotlinx-coroutines）。桌面端可用 JVM + Room（SQLite JDBC）、网页端可移植为 SQLDelight/Exposed，按相同语义实现 Repository。
3. **复用路径 B（直连数据库）**：桌面工具直接打开导出的 `.db` 文件或读取 xlsx/JSON，表结构与上述模型一一对应。
4. 扩展新功能（如照片附件）时新增表并 `schemaVersion+1`，保持旧字段不动即可双向兼容。
   - v3：新增 `plannedItems`（柜子实例的预选待测清单）
   - v4：plannedItems 增加 `result`（0未测/1通过/2未通过）与 `faultId`（未通过关联的故障）
   - v5：新增 `debuggers`（调试员名单；name唯一；合并时同id新者胜、按name去重、改名撞名跳过）
   - v6：新增 `deletedItems` 删除墓碑（tbl=被删记录所在表名, itemId=原UUID）；合并端先落库墓碑→按表应用删除（触发与本机一致的级联）→跳过已删id与孤儿行
   - v7：`instances` 增加 `shortName`（精简名，网格视图显示用）
   - v8：`instances` 增加 `sortOrder`（拖动排序，0=默认按名称）
   - v9：`instances` 增加 `rowGroup`（行分组编号，0=未分组）
   - v10：顶层增加 `deviceTimeZoneOffset`（时区偏移毫秒，同步冲突裁决）；新增 `deletedProjects` 项目级删除墓碑；`readyKind` 区分 full/global/project 三种快照子集
   - v10/DB v11：项目/类型/柜子/日志/故障/预选项/调试员删除仍写 `deleted_items`，**项目删除改走独立 `deleted_projects` 表**（app 内建库 version 10→11，迁移链完整）
   - v11：`logs` 增加 `logType`（0通过/1故障/2消除，随快照同步多端合并不再回退为「通过」）；旧备份缺该键按 0 解析，兼容读取
